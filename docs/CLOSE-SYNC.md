# 收盘价自动补齐

用户已授权增加独立后台收盘同步，取代初版“只手动刷新、不建计划任务”的限制。没有新增消息提醒或交易操作。

Cloudflare Cron：`* 8-15 * * *`，UTC换算为北京时间每天16:00—23:59每分钟触发，程序只在16:05—23:55执行采集。用独立市场日历跳过休市；日历超出覆盖时暂停并显示原因。网页无需打开。首轮不是承诺每个供应商在16:05已发布完整数据，未取得的收盘价持续查漏。

用户当前范围：每笔采集买入当天D0及之后D+1至D+10收盘价，D+11不采集。旧版本已有的历史数据保留，不自动删除。昨天录入的股票今天收盘后会补D+1。未发生的日期不查询为真实价格；完整D+10后不再为这笔样本取新日期。窗口结束仍缺报价时继续尝试历史补齐，不生成窗口外收益。北交所日历仍未核实，暂不自动补其D+n，状态页明确说明。

选择待同步记录不依赖策略分析范围、P0或公司行动核对：所有原始买入样本都可补行情，收益计算仍遵守原有价格与公司行动限制。多个策略、时点的相同股票共享一次查询，样本独立保存。缺少当日有效报价不填0或前收，不自动认定停牌。

每个新增收盘价用东方财富与腾讯同日期不复权收盘逐条比对，严格一致才采纳，记录两家来源、原始价格和核对时间；来源不一致或缺少第二来源时保持待核对、重试，不静默选一家。手动刷新同样执行交叉验证。定时请求绕过普通5分钟行情缓存。按时间戳检查已获取的当前收盘数据，已齐全不重复请求。每次最多8只证券，同时查询2只，保留每次最多48个上游请求及SQL预算，重复样本多时分批处理；当日未尝试证券优先；失败证券至少间隔10分钟再试，等待重试的证券仍计入待处理数。跨策略和买入日期的同股票共享查询。运行时间超过一分钟时重叠轮次跳过，实际吞吐仍受接口耗时影响。数据量超出可处理范围会显示待处理数量，不声称全部完成。

网络失败不改变旧行情及其获取时间，只保存错误；部分历史数据可补齐但仍缺当前报价时保留原有价格并合并新有效点，显示缺少的日期。更新以记录revision为条件，避免覆盖并发修改或已删除记录。运行锁防止15分钟内重叠；停滞锁可过期恢复。

`0003_close_sync.sql`只新增运行记录与每证券尝试状态两个表，不修改现有表或买入数据。正常发布前迁移；首次后台执行或状态读取也可兼容初始化。状态保留最近30天（当前执行中的条目除外），不把股票明细写入公开日志。运行信息只有登录后可读。

数据与设置页展示首次待执行、执行中、跳过、成功、部分完成、失败及待处理数。必须等待生产Cron真正执行并核对结果，不能把本地模拟或Cron配置保存当成真实自动更新成功。

验证：`npm test`测试时间、窗口、去重、缺价与免费预算；`npm run test:scheduler`使用隔离D1与明确的测试行情，验证无网页执行、请求去重、缺值、网络失败、补齐和锁。测试行情不写入生产。
