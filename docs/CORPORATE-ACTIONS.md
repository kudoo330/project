# 观察期内除权及冻结

用户要求：只在买入后10个交易日观察期未结束时，将历史计算价格调整到除权后的可比口径。这里按市场交易日历定义结束：D+10收盘，而不是缺数据导致统计迟迟未完成。D+10当天的公司行动纳入最后快照，之后新发生的公司行动不影响该笔记录。

## 数据和计算

原始人工成交价、分钟参考价及不复权行情不改写。计算用价格与基准另算并清楚展示。

新浪`finance.sina.com.cn/realstock/company/{symbol}/hfq.js`提供因子及生效日期。使用后复权累计因子H做相对转换，等价于以观察期当前除权后时点锚定的前复权：

`计算价格(t) = 原始价格(t) × H(t) / H(锚定日)`。

P0使用完全相同的买入日因子转换，因此不会只降低之前收盘价却保留原始成本，制造假亏损。股数和真实现金不变；这仍是调整价格观察，不声称含税费、真实现金分红或已实现投资收益。

因子必须与腾讯`qfqday`前复权日线交叉核对，腾讯价格重新锚定到相同日期后比较。腾讯日线价格按分报价，再次归一化会增加舍入误差，允许最大0.021元差异；不采用比价结果反推因子。原始收盘价仍须通过东财与腾讯不复权价格的严格核对。买入日前复权因子也须有可核对的买入日日线，不能盲调人工价格。

因子缺失、响应异常、锚定日完整收盘缺失或交叉检查冲突时，继续保存已验证的原始收盘，但将复权与收益标为待核对。观察期内后续Cron继续查漏；不伪造因子、不关闭TLS或运行供应商JavaScript。解析仅用JSON。

## 人工确认现金分红

部分现金分红中，新浪使用比例因子，腾讯直接从历史价格减去现金分红，两种口径可能超过原有价差阈值。管理员可通过 `POST /api/confirm-dividend` 提交 `record_id`、`revision`、`date`（除息日）、`cash_per_10`（每10股派现金额）及 `reason`。仅作用于指定样本的未结束观察期，不改变原始买入价和日线。

此入口不会强行通过核验：必须有实际因子变化、已交叉核对的除息前一交易日收盘，且新浪相对因子等于 `(前收盘 - 每股现金) / 前收盘`（倍率误差最多1e-8）。当两家算法不同，还要求窗口内所有因子变化均有人工现金方案，逐日核对腾讯价格等于原价减去之后的已确认现金（最多0.021元舍入差异）。未知新事件、缺来源、缺原始交叉验证或不能解释的价差继续阻断。

使用比例算法同步转换计算价与P0，D0涨跌幅仍为原始买入价与原始当日收盘之比。`confirmed_cash_dividends` 保存人工来源、依据、操作人与时间，刷新和补价时保留；`adjustment.verification=admin-cash-dividend` 明确区分人工方案核验与原来的双源同口径核验。审计保存原记录与新确认，版本及行情内容双重比较防止覆盖并发更新。方案有误可在观察期内以新版本重新确认，未通过不写入；D+10之后不追溯处理。

## 快照与冻结

每笔`market_data.adjustment`保存锚定日、基准倍率、每日倍率、事件日期、所用因子、核对时间、状态和冻结标识。`adjustment_source`只保留买入日至D+10所需证据，不在每笔记录中堆放整段600日日线；`adjustment_history`保留最多20个过往口径快照。

D+10取得最后有效快照后冻结。之后供应商因新除权更新历史前复权数据，也不替换该笔计算因子及因子证据。结束时未完成核对的记录保留待核对，不在后来偷偷追溯复权。既有已结束的老记录不自动修改。

盘中或休市时手动刷新，以最近已收盘交易日为锚点，避免混用盘中公司行动和完整收盘。

## 验证与限制

5项确定性测试覆盖拆股、现金分红、P0同步调整、D+10冻结、老记录不改与来源冲突阻断。

实际公开历史样本：600519.SH，买入研究时点2026-06-25，因子生效日2026-06-26。实际读取东财18日日线、新浪因子、腾讯18日前复权日线，当前算法通过交叉检查，买入基准倍率为0.9768796056430945。只用于研发验证，没有写入用户买入记录。原响应及验证结果位于云工作区scratch。此证据不等于生产Worker网络或自动任务已验证。

因子生效日不是已人工核实的官方公告文本。配股参与、特殊公司行动或来源计算方法不一致时可能阻断，需要另行核实，不声称覆盖所有公司行动。北交所按用户2026-10-19确认与沪深使用相同交易日历，适用相同的除权核对及D+10冻结规则；来源不足仍阻断收益。
