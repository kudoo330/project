# 策略分析范围

每个策略独立保存分析范围，默认全部样本；其他策略不继承这个配置。策略比较页的“分析范围”可单独或组合启用：

- 每个买入日期最早N条（默认建议10，可设1—500）。
- 严格早于指定上海时间（默认建议13:00:00，13点整不计入）。

组合顺序：按买入时刻筛选，再在每个策略、每个买入日期内取最早N条。先买入时间升序，再创建时间升序，最后样本ID升序作为确定性同秒平局规则。按样本数取N，重复股票占不同名额，不按不重复股票去重。

选取不依赖价格是否齐全：缺价样本仍占名额，不换入后续有收益的样本；每个D+n只在入选样本中使用有效值计算均值和正收益比例，显示有效分母。未来、缺价、未经公司行动核对的值继续为空。

页面展示两个跨策略汇总：原始全量（保留既有口径），以及各策略分别应用规则后合并的入选样本。后者直接按入选策略样本等权，不对策略均值再次平均。原始看板、导出和数据库记录全部保留。

“查看入选范围”显示入选 / 排除及原因、原始数、入选数、排除数；显示的明细受记录接口5000条加载上限约束，页面明确说明。正式汇总由服务端使用全量记录计算；本地预览不是最终分母。

范围是动态设置，对该策略当前和历史样本统一重算，不是每笔买入时的规则快照；修改不会删除记录。若后续需要版本化分组对比，应另行添加分析配置版本，不暗中改变这个定义。

## 持久化与升级

`strategy_analysis_rules`按稳定策略ID保存JSON规则、乐观锁版本、修改人和时间。不是浏览器偏好或过期行情缓存。策略重命名 / 归档不删除规则。`PATCH /api/strategies/:id/analysis-rule`仅管理员可写，要求同源和匹配revision；并发覆盖返回409。

迁移 `0002_strategy_analysis.sql`只`CREATE TABLE IF NOT EXISTS`一个新表，不修改、删除原表与记录。正常部署命令`npm run deploy`在发布前应用版本化迁移。兼容已有控制台直接部署路径：Worker首次访问策略配置时也从同一个版本化SQL文件初始化该表，无需用户手工SQL；失败不标记初始化成功，下次请求可重试。后续CLI迁移重复执行安全。

## 验证

5项新增单元测试：每日及策略隔离、严格秒边界与组合、同秒平局和重复股票、非法参数、服务端权重与缺价名额。新增API / 浏览器验证：持久化、跨策略隔离、409冲突、只读拒绝、原始记录不变、编辑预览保存重载与恢复全部。
