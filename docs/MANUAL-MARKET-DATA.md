# 历史行情手动导入

这是 v3.0 的一个独立交付切片：先保留缺口，再由管理员补入历史行情。它不代表完整 v3.0 已交付，也不改变原 A 股记录、D0—D10 计算和自动收盘采集。

## 使用

管理员登录后，在「数据与设置 → 历史行情手动导入」打开 `/market-data.html`。支持 AMD.US、AMDL.US 的 1 分钟与独立日线；每批 1—500 行，完整请求不超过 800,000 UTF-8 字节。包含旧值的修订记录超过 1.5 MB 时，明确提示拆分为更小批次。

1. 选择股票、周期、数据来源、复权方式并填写来源依据。前复权必须指定截至日期，不同来源、周期和复权截至日期保存为不同数据集。
2. 上传或粘贴 CSV / JSON。空白 CSV 表头可在页面下载；不注入示例行情或虚拟持仓。
3. 预览格式错误、新增、补齐、相同与冲突行。预览不写库；修改内容后需重新预览。
4. 确认导入。已有价格发生冲突时，须勾选替换并填写依据；旧值、操作者和来源保留在修订记录。缺失行不能覆盖已有有效价格。
5. 按数据集和美东日期浏览、分页及导出。单次导出最多 5,000 行；超过限制明确拒绝，不截断。

CSV 基础表头：

```csv
time,open,high,low,close,volume,status,reason
```

分钟 `time` 表示分钟开始时间，必须带明确 UTC 偏移或 `Z`，且秒数为 00；统一保存 UTC，保留原始时间和美东日历日期。分钟筛选不自动将夜盘归入下一交易日。美东时间请使用实际夏令时偏移。日线 `time` 为纽约交易日 `YYYY-MM-DD`，不从分钟数据合成。

`available`（默认）需要有效且关系一致的 OHLC；成交量可为非负整数或未知的空值。以下状态的 OHLC 必须全部为空且填写原因：

| 状态 | 含义 |
| --- | --- |
| `missing` | 缺少价格 |
| `not_entitled` | 来源权限不足 |
| `request_failed` | 请求失败 |
| `no_eligible_trade` | 来源明确确认没有合格成交 |

缺价不推断停牌，不以 0、前值或相邻分钟填补。没有输入的时段保持未知，不计为完整覆盖。未来或尚未结束的分钟不能导入为完整行情；当日日线须到美东 16:00 后。此时间检查不等于完成美股节假日、半日市或供应商终值验证。

## 接口与存储

所有 `/api/research-data/*` 接口仅管理员可用；旧查看者和只读密钥不能读取这些行情。写入还要求同源与 JSON。浏览器不保存数据源密钥。

- `GET /datasets`：数据集和行数。
- `POST /preview`：规范化、校验、冲突检测，返回版本与预览摘要。
- `POST /import`：携带预览摘要、预期版本、唯一 `request_id` 提交；相同请求可安全重试，过期预览返回 409。
- `GET /bars?dataset_id=…&start=…&end=…&limit=200&cursor=…`：分页读取；日期范围按美东日期包含首尾。
- `GET /export?dataset_id=…&start=…&end=…`：CSV 导出，包含来源、复权和缺失原因，防公式注入。

迁移 `0005_research_data.sql` 仅新增四张 `research_market_*` 表。数据、批次、修订记录通过同一 D1 原子批次写入，用数据集版本防止并发覆盖。它不更改 `records`、`strategies`、旧审计和旧行情缓存。

所有手工导入行情标记为 `unverified`。校验 OHLC 和时间格式不等于独立来源交叉验证；不自动继承导入文件自称的验证结论。

## 部署与恢复

已有生产库必须先完整导出 D1 到受控位置；网站记录 CSV / API 快照不是完整数据库备份。然后执行正常版本化迁移和部署。推送已绑定的生产分支会触发 Workers Builds，须在推送前完成备份。

代码回退可恢复旧 Worker，新增研究表仍保留；不通过删除旧表或重建数据库回退。完整恢复应先将备份导入新库并验证，再切换绑定。新库本地测试通过不能代替生产备份或恢复演练。
